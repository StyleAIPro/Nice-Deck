# AICO-PPT 编辑准确性、稳定性与速度改造方案

日期：2026-09-08。状态：核心实现及回归完成，正在桌面试装验收。以下原始依据与预算保留供对照，实际范围见文末。

## 目标与顺序

先保证编辑状态可恢复、可重放、可固化，再减少模型往返和重复渲染。用户正常描述意图即可，不要求关键词，也不要求退出右侧 Editor。小修改应保持小范围，不能默认增加排版重构。

## 已确认的依据

- C3 会话“删掉这块”一轮耗时约 9 分 14 秒，16 个模型步骤、18 次工具调用、一次上下文压缩。任务本身是删除建设计划页右侧栏，Agent 额外扩宽了左侧容器。
- `scripts/editor/dsh-agent-run-adapter.mjs` 每批指定 `loadSkill:true`。日志中先注入用户级 Skill，再读取安装包 Skill，后续还读取设计规范、创建背景和协议。
- 区域候选返回侧栏的四个子元素，未直接返回侧栏容器，导致 Agent 读取源码、查协议、定位父容器。
- `integrations/dsh/editing-context.mjs` 每步解析连接并注入完整工作区说明。本轮有 16 次；尚未证明 Harness 请求中的历史快照是否全部保留，不能把 UI 记录数量等同于上下文增长量。
- `bridge-service.mjs` 已有串行写入、commandId 去重、提交确认、受影响页诊断。不新建一套平行写入或校验机制。
- CLI `verify` 调用 `/api/write-deck`；托管工作区分支并不执行与真正固化相同的离线补丁候选重放。现有验证通过不能等同于“可固化”。
- 新截图中的固化错误已用只读输入和临时候选文件复现：revision 59，`PATCH_REPLAY_FAILED / TARGET_AMBIGUOUS`；失败动作 `8a29f682-456a-42f5-8b5d-c5eae84573b9` 是把建设计划页左侧容器从约 1342×829 调整到 1740×829 的 resize。此后发生了 SourceMutation，固化时该动作不能匹配。复现脚本：`/tmp/aico-solidify-candidate.mjs`，临时脚本不作为长期测试资产。
- `checkpointWorkingDeckChange` 主要验证工作副本内嵌的已固化补丁；当前未固化动作没有一起经过相同的候选重放闸门。新错误证明两种检查覆盖范围存在缺口。最终基线尺寸、语义匹配的具体修复仍须通过最小回归案例确认，不能仅按持久 ID 放行。

## 一、按实际操作分级

| 流程 | 程序判定依据 | 必做检查 |
| --- | --- | --- |
| 直接编辑 | 唯一目标，已有文字/样式/移动/缩放/显隐动作可表达；影响范围可确定 | 身份、版本、动作起始值、持久化、受影响页诊断；按修改类型提供结果图 |
| 局部结构修改 | 改 DOM、布局或增删元素，影响限于局部容器/页面 | 上述检查，加源码事务、完整历史候选重放、受影响页视觉核对 |
| 完整修改 | 增删排序页面、共享 CSS/脚本、模板和导航变化，或依赖范围无法证明 | 结构一致性、完整历史重放、全局影响检查及必要的全页/动画验证 |

模型表达意图和提出动作，程序根据动作类型、目标和实际源码差异决定检查范围。不能因为模型说“简单”就跳过保护。批量改几十个明确元素仍可走直接编辑；一行全局 CSS 修改可能需要完整检查。

目标不清时先补充父容器、候选关系和截图，仍不明确才请用户定位；不把歧义自动升级为整套制作。局部检查发现外溢影响时扩大验证范围。网络失败和版本变化只进入恢复流程，不重新加载制作规范。

删除元素需区分隐藏、移除并补位、删除整页；保持现有 hide 语义透明。用户只要求删除时，不自动扩宽、重排其他内容。

## 二、统一有效状态与重放规则（P0）

维护一个内部有效状态模块，以权威工作副本、已固化补丁、当前时间线与游标生成同一候选。供预览恢复、源码提交、截图、导出与固化调用；沿用已有 compiler、runtime、sidecar，不新增第二套历史数据。

1. SourceMutation 提交前，在临时候选上验证已固化补丁和当前有效未固化动作，不能只验证内嵌补丁。失败则按原事务回滚，不登记为成功。
2. 把纯状态检查、当前页诊断、完整重放与发布明确区分。普通检查不得伪装成写操作或推进内容版本；真正发布仍需文件身份、指纹与原子写入保护。
3. 对源码变更后已被吸收或取代的动作，只在前后版本、唯一身份、属性语义和当前值能证明一致时记录受控转换。保留转换记录，撤销源码修改能恢复原动作；不能批量删历史、放宽全部浮点比较或仅凭 editorId 猜测。
4. 固化使用已经验证的精确候选；候选与当前状态不一致就失效。避免验证一份内容、最后写入另一份内容。
5. 错误返回页码、动作、目标摘要、冲突阶段和恢复选项。区分“目标歧义”“历史值冲突”“画布离线”“已提交但检查未完成”；错误码不能全部显示为请补充描述。

当前用户会话先备份并生成复现夹具；修复通过后再从原始有效历史重建恢复方案。任何无法证明的动作单独保留、定位处理，不要求清空五组修改或覆盖源文件。

## 三、给 Agent 一个简洁的编辑入口（P1）

建议以三个逻辑操作组织 Agent 接口，名称实施时再确定。CLI 与 Harness 工具共用同一实现，保留独立 Skill 使用方式。

- **查看任务**：一次返回任务、权威状态标识、当前页摘要、区域图、唯一目标或候选及父容器关系、允许的动作。自然语言修改也能按页面/目标查询，不强制创建区域任务。
- **提交修改**：接收任务、目标引用、动作、expectedRevision 和 commandId；内部复用 prepare → journal → ACK → 页面诊断，返回修改结果、同步/检查状态、受影响页和可选截图。
- **查看结果**：按原 commandId 读取已提交结果和检查进度，或查看当前页；不重新执行动作、不拉取整个会话历史。

目标引用绑定工作项和读取版本；服务端解析完整 locator。返回原样可使用的父容器与后代关系，避免 Agent 根据字符串路径拼父节点。仍需检验 tag、持久身份、属性起始值及文字范围。

常规操作提供短小的工具描述与示例，不要求 Agent 查 `protocol.mjs` 或写一次性脚本。初期可让 CLI 内部完成编排，随后通过 PPT 自己的 Harness 集成暴露原生工具；不要把 PPT 协议写进 Harness 核心。

## 四、视觉确认直接使用当前修改（P1）

复用 Harness 的 Electron 渲染能力，提供带工作项、页 ID、状态标识、渲染参数和检查范围的图片结果。Agent 可以直接看图，无需先生成截图脚本。

- 权威状态标识至少包含工作副本指纹、已固化补丁摘要、有效动作摘要和渲染运行时版本；渲染参数包含页、视口、字体/资源就绪、主题及动画层状态。session revision 仍用于写入保护，不能只用文件 SHA 判断截图是否最新。
- 默认返回受影响页面的标准分辨率图，必要时同时提供目标附近裁剪图。必须包含未固化动作，并明确是标准渲染还是现场视图。
- 在隐藏渲染页中物化同一权威候选，等待字体、图片和布局稳定；设置最大等待时间，缺资源明确报告。不要滚动、切页或改变用户正在看的画布。
- 精确现场截图可另走当前 Editor 渲染确认后的画面捕获；多层 iframe、缩放、遮挡与动画状态须测试后再宣称“与现场完全一致”。已有 html2canvas 区域快照可继续辅助定位，不能当作所有 CSS/SVG 都准确的最终截图。
- 按内容状态和渲染参数缓存图像/检查结果；有容量和生命周期限制。先测初始化耗时，再决定复用隐藏渲染页，禁止跨工作项混用内容或无限缓存。
- 截图失败时显示“修改已提交、视觉检查未完成”，不能伪装成修改失败并再次提交。

## 五、减少重复上下文和无效重试（P1/P2）

1. 移除桌面每批 `loadSkill:true`。以会话、插件版本、规范摘要维护已加载状态；会话压缩后只恢复必要的编辑契约。新建整套 Deck 才加载制作规范，局部编辑按需读取对应小节。
2. 固定本会话所用 Skill 来源与版本，消除用户级路径和插件包路径的重复加载。运行时凭据不缓存为旧 token。
3. 将连接状态与稳定操作说明分开。检查连接仍可每步进行；相同上下文快照应按 Host 正式机制替换或去重。先验证实际请求行为，断线、换工作项和插件升级必须立即更新。
4. 标准修改提交结果已含任务完成与页面诊断时，不重复调用 task、verify。需要独立检查的，只检查缺失部分；保留全量检查入口供结构变更与发布使用。
5. 传输超时先查询 commandId 结果；确认未提交且前置条件未变才重试。同一 commandId、同一内容去重，同一 ID 不同内容拒绝。真实 before/after、源文件或目标变化交给重新规划，不能自动换 revision 后覆盖。
6. 只读检查遇到新版本时可以有界地检查最新状态，但结果须注明检查版本及原提交是否仍有效；用户持续编辑时返回待检查，不无限循环。

## 六、职责与实施批次

| 批次 | 交付内容 | 主要位置 | 放行条件 |
| --- | --- | --- | --- |
| P0 稳定性 | 当前固化失败回归；有效状态编译；结构提交覆盖全部有效动作；明确检查与发布语义 | compiler、working-deck-store、server、bridge-service、runtime | 原案例可重开/固化，原文件不误写，历史可撤销 |
| P1 编辑入口 | 完整目标/父容器摘要；提交结果整合；按需规范加载；标准操作示例 | agent-runner、dsh-agent-run-adapter、PPT 集成、CLI、frame-bridge | 小任务不查协议源码、不重复读完整 Skill、不额外改版式 |
| P1 视觉闭环 | 同版本截图、局部图、图片结果直接供模型读取 | PPT 验证模块与集成；必要时扩展 Host 通用渲染能力 | 未固化修改可见；状态改变时旧图不冒充最新结果 |
| P2 性能与恢复 | 去重上下文、有界重试、检查缓存、可观测耗时 | editing-context、现有命令结果与诊断机制 | 并发人工编辑不丢失，无重复修改，性能基线改善 |

Harness 只负责通用工具承载、图片读取/返回、渲染和模型上下文机制。PPT 负责编辑语义、目标、事务、历史、检查范围与恢复。其他未来 AICO 插件可复用 Host 能力，不依赖 PPT 内部状态。

## 七、验收与性能衡量

记录任务分级、模型步骤、规范读取次数、输入输出量、定位/提交/同步/诊断/截图耗时、冲突与重试原因、首次可见结果及最终完成时间。统计不记录凭据，不把思考内容当指标。

回归矩阵：改字、字色、移动、连续缩放、隐藏容器、删卡片并补位、删页、共享样式；分别覆盖中文/富文本/SVG、83.33% 与其他缩放、已有大量历史、源码与动作交错、撤销/重做、断线重开、人工并发、固化与导出。加入目标 ID 重复、同 ID 内容更换、文字范围变化、保存失败等拒绝误改用例。

每项修改都检查：预览与候选内容一致，截图版本正确，重开可恢复，固化后离线重放正确，原文件仅在发布成功时改变。SourceMutation 失败后工作副本与历史一并恢复。

性能目标先作为预算，不当作已达成的承诺：

- 已就绪、目标明确的小修改，通常 2–4 个模型步骤完成含看图确认的流程；零次重新完整读取 Skill，零个临时验证脚本。
- 首轮以现有“删除侧栏”记录作端到端参照，用同模型、相近上下文和固定任务集重复测量；目标减少至少 70% 的模型往返，避免把一次最慢样本当唯一基准。
- 本地标准修改在固定六页/大历史测试集上分别报告冷启动、热运行 p50/p95；初始热运行预算为提交及局部诊断 p95 ≤ 3 秒，含一页截图 ≤ 5 秒，测得超预算后按具体阶段优化。模型延迟和外部资源等待单独统计。
- 零重复提交、零静默丢失修改、零跨版本截图误报；任何提速不得通过关闭身份、历史、文件指纹或固化重放校验实现。

实施时先补最小失败回归，再改实现；用同一公开编辑入口完成集成验收。每批通过后才构建安装包并在桌面验证，不把源代码测试等同于已安装版本测试。

## 本次实现记录

- `effective-deck.mjs` 复用既有编译器与物化器生成含未固化动作的候选，供源码提交、恢复、纯 verify 和标准截图使用。原子固化、导出继续使用同一编译器及物化器。
- SourceMutation v2 按归档指纹保存静态文字覆盖、相同尺寸声明证据和实际影响范围。旧会话重建证据，缺失动作仅经浏览器确认后按源码转换归档，撤销仍可恢复。原 C3 revision 59 候选已通过重放。
- 原生 `aico_ppt` 提供 inspect/edit/view/result/verify，与 CLI 共用 Editor HTTP 接口。提交复用串行、幂等命令、ACK 和受影响页诊断，图片通过 Host 正式附件服务返回模型。
- 标准图包含未固化动作，最多缓存三张、并发两次，同状态请求合并。尚无现场窗口截图；多页提交先返回第一页，其余受影响页可继续 view。
- 桌面任务短提示、同轮稳定上下文去重、只读有界重试、提交阶段耗时已接通。连接与凭据即时读取，截图失败不重复修改。
- 模型端到端 p50/p95、跨平台性能矩阵和全类型视觉回归仍需固定任务集持续测量，不将本地回归结果当作全部性能预算已达标。
