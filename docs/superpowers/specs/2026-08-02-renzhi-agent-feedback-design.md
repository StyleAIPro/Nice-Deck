# 认知 Deck 四条 Agent 意见修订设计

## 目标

对 `Deck-Projects/renzhi/renzhi-deck.html` 落实当前编辑器队列中的四条意见，并恢复页面 6 被误移动的右栏标题。最终 Deck 保持 1920×1080、离线单文件、华为红品牌风格，并通过 bundle、溢出和截图验证。

## 已确认范围

1. 恢复页面 6 右栏标题 `Model Training Taskforce Incubation & Enablement` 到原始位置，去除当前会话累计的约 `+70px / +133px` 位移。
2. 页面 6 保留双栏三卡结构，只放大卡片内文字并利用现有留白。
3. 页面 7 保留页标题、副标题和 `1. Platform Construction` 区域。
4. 页面 7 删除五个指标卡、来源说明和底部总结文案。
5. 页面 7 的下半区采用用户确认的 A 方案，按参考图重绘远近一体化协同作战机制。
6. 本轮不修改编辑器的全局撤销、附件等产品功能。

## 页面 6 设计

- 主题编号从 `21px` 放大到 `24px`。
- 两栏主题标题从 `30px` 放大到 `32px`，保持原始位置和层级。
- 六个正文块从 `22px` 放大到 `28px`，行高约 `1.32`；长句允许自然换行。
- 卡片、背景、边框和三段式内容结构保持不变，不新增装饰元素。
- 最终源文件不保留任何来自误拖拽的 `translate` 样式。

## 页面 7 设计

### 保留区域

页标题、说明文字和 `1. Platform Construction` 四张能力卡保持现状。原有 `data-step="0"` 动画节拍保留。

### 协作机制图

原 `2. Collaborative Operating Model` 及其下方区域合并为一个约 560px 高的白色主面板，作为 `data-step="1"` 整体出现。图中使用纯 HTML/CSS 绘制，不把参考照片嵌入 Deck。

主图结构：

- 左侧椭圆：`On-site FAE / Project Teams`；说明需求沟通、现场部署与验证。
- 中间椭圆：`OCC Operations Center / Central Hub`；说明可行性分析、方案设计、迁移调优与 OpenLab 验证。
- 右侧虚线椭圆：`Remote Expert Virtual Team`；说明深度调优、重大疑难问题定位与解决。
- 左中之间使用上下双向链路，标注迁移调优需求、疑难问题、部署指导书与模型脚本。
- 中右之间使用上下双向链路，标注深度调优需求、疑难问题、调优方案与模型脚本。
- 底部平台矩形：`Intelligent Operations Platform / Agent Platform + OCC System`；三方通过灰蓝虚线连接到平台。
- 平台左右补充 Agent 开发职责与团队来源，但控制为两行以内，避免信息拥挤。

颜色只使用华为红 `#b5333b`、灰蓝 `#566472`、中性灰和白色。红色用于标题、关键角色和主要链路，灰蓝用于辅助线和说明文字。

### 删除内容

- `57 / 250+ / 220+ / 85%+ / 30,000+` 五张指标卡。
- `Source: AICO platform...` 来源说明。
- `The platform connects...` 底部总结。
- 原四角色横向矩形流程条和旧闭环说明。

## 保存与恢复

当前编辑器动作协议只支持 `setText`、有限 `setStyle`、移动、缩放和显隐，无法新增 A 方案需要的图形节点。因此本轮使用 `scripts/edit-bundle.py` 对页面结构进行安全修改，不扩展编辑器协议。

执行前关闭当前编辑服务，将现有 `.huawei-deck-editor` 会话目录改名归档；归档中保留任务 JSON、四张选区截图和旧 revision。再保存一份修改前 Deck 到归档目录。修改完成后启动全新编辑会话，以最终 Deck 为新基线。

这四条意见作为一个结构性修订版本恢复，不承诺四条分别出现在旧会话的 UI 撤销栈。需要整体回退时，从归档的修改前 Deck 恢复。全局撤销与结构性动作支持属于后续独立功能。

3. 分别生成页面 6、7 的 1920×1080 截图并目检。

5. 重新启动编辑器并读取新会话，确认 Deck 可加载、旧误移动不再重放。
