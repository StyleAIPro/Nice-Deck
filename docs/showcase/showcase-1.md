## 第一幕 · 目标讨论：四个问题锁定方向

不急着做页。AICO-PPT 先用四个选择题把需求钉死——**场合、时长、交付、素材**，每个选择直接决定模板与结构。

![问题一·场合：选「毕业答辩汇报」](image-11.png)
**① 这份 PPT 用在什么场合？** 选「毕业答辩汇报」——于是自动定调：结论先行、页数精简、留时间给问答，用 41 页工作汇报模板做底。

![问题二·时长：选「30 分钟以上」](image-12.png)
**② 现场汇报多少分钟？** 选「30 分钟以上」——正文预算约 16–18 页 + 附录，页数据此规划。

![问题三·交付：选「HTML + PPTX 都要」](image-13.png)
**③ 最终交付什么格式？** 选「都要」——HTML 版保留点击动画与放映体验，PPTX 版满足答辩系统留档，初版就先试导一次 PPTX 验证链路。

![问题四·素材：勾选代码仓库 / 论文 / 截图 / 项目目录](image-14.png)
**④ 项目素材在哪？** 一次勾齐：本机代码仓库、论文与开题报告、实验截图，并直接给出整个毕业设计文件夹路径——AI 可以自己去读。

![四问答案汇总确认](image-15.png)
**Review**：四个答案一屏复核，确认无误再提交。需求共识在动手前就达成，避免返工。

![真料：毕业设计文件夹目录一览](image-37.png)
**这就是喂给 AI 的「真料」**——论文答辩 PPT、毕业论文说明书、开题报告里的多篇降维综述、`程序/` 下的 MATLAB 代码（LSRGE-release）、现成实验图（`PCA_Yale_B` / `LPP_ORL` / `LSDA_ORL` / `NPE_Yale`）、`分类结果.xlsx`。有真料，deck 才不是空壳。

## 第二幕 · 主题讨论：读透真料，三轮敲定大纲

AI 把论文和代码读完，先把**需求共识**和**大纲提案**摆出来，你点头才动模板。

![需求共识 + 首版大纲提案](image-16.png)
**吃透项目**：认出题目《基于图嵌入正则化的降维方法研究》，核心是回顾经典图嵌入降维算法（线性 PCA/LSDA/SPP、流形 LLE/LPP/NPE）、重点研究 **GLSRGE**（同时保留全局与局部结构）。给出「结论先行」的六章大纲表，连每章分钟数、页数都排好。

![第二轮：改成「当年答辩复刻升级版」](image-17.png)
**一句话调方向**：你说要保留「当年答辩」的研究时间线与学生视角收获，AI 立即把定位改成「复刻升级版」，按「项目背景 → 研究过程 → 成果展示 → 收获体会」的回顾式叙事重排大纲。

![第三轮：终稿候选大纲，理论拆成专章](image-18.png)
**再细化**：把理论从「研究过程」里拆出来独立成章讲透，合计正文 22 页 + 附录 3 页 = 25 页，约 35 分钟——精准命中「30 分钟以上」。确认后回一句「开工」。
