# 0.1.36：图片附件内嵌与加载验证

2026-10-16。针对用户截图中的 `[bundle] error`，修改范围在 AICO-PPT；原装宿主与 Harness 没有改动。

## 原因与修复

真实 `structure.insertFragment` 请求把 Windows `C:/Users/...png` 路径直接写入第 3 页「容量与通信约束」的图片。浏览器将 `c:` 视为未知协议，图片宽度为 0。三个资源错误来自同一张图片，未发生 JavaScript 异常；全局错误栏在第 12 页仍可见。旧验证器只判断编辑补丁重放成功，漏过了图片失败。

- `replaceImage` 新增 `attachmentPath`。局部 HTML 的 `img.src` 如果指向当前 Deck 已登记附件，也自动写入 manifest。支持 PNG、JPEG、GIF、WebP，单次总量不超过 25 MiB；复用可信 sidecar 目录和文件读取，不按任意模型路径访问文件。Windows 同时识别已绑定目录的短路径、真实长路径、正反斜杠。
- 完整候选验证等待 bundle 解包和补丁重放，逐张检查图片解码，失败返回 `RESOURCE_LOAD_FAILED`、所属页、元素编号和图片信息。局部事务取消并确认回滚后才报告 `committed:false`；持久化状态不明仍保留原有保护。
- 五套模板共用具体资源错误栏，重复事件去重，地址移除查询参数和凭据。`edit-bundle.py` 写回已知外壳时更新此错误栏；安装本身不扫描或改写用户 Deck。
- 包含 0.1.35 的“开始”导航与此前修复。工具描述、Skill、编辑指南和安装文档同步。
