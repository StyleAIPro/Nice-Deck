# workflow.md — 从零做一份 PPT 的七阶段协作流程

**总原则：三个「讨论」阶段都是硬闸门——没拿到用户明确确认，不进入下一阶段。** 返工最大的来源就是跳过阶段 1、2 直接开搭页。本文只管流程与产出；建 deck 的机械操作（复制模板 / edit-bundle / verify）见 SKILL.md 快速上手与 `editing-guide.md`。

流程对**授课 / 汇报 / 学习材料**通用；阶段 1 问清场合后，先按下面的场景适配表定基调，后文各阶段中的授课经验值按表换算。

## 0. 场景适配表

| 维度 | 授课 / 培训 | 汇报（进展 / 方案 / 述职） | 学习材料（自读） |
|---|---|---|---|
| 叙事骨架 | 抛问题 → 讲原理 → 看实践 → 巩固收尾 | **结论先行**：背景一页 → 结论 / 诉求 → 论据与数据 → 风险与下一步 | 手册式：总览 → 分主题逐节展开 → 速查小结收尾 |
| 页数节奏 | 1.5–2 分钟/页，40 分钟 ≈ 20–25 页 | 用时间的**一半**做页数预算（10 分钟 ≈ 5–8 页），留一半给问答；备查内容进附录页 | 不受时长约束，按主题完整性定页数；单页信息密度可更高 |
| 页型倾向 | 全部可用；问题页 / 黑板题卡 / 研讨页 / 动手实验穿插互动 | 截图对照 / 表格混排 / 密集多栏 / 全幅大图（用数据和硬结论说话）；**别用黑板题卡、研讨页**（课堂专属） | 各版式可用；金句页做章节小结；动手实验页可留给读者自己操作 |
| 动画用量 | 按讲课节拍整拍设计 | 少用或不用——汇报常被打断、常导 PPTX 静态翻阅 | 基本不用——没有讲者推进，读者滚动浏览 |
| 语言风格 | 口语化，可用类比、设问、emoji 梗；页面留钩子，细节由讲者展开 | 书面结论化：判断句 + 量化数字（写「提升 1.76×」不写「快了很多」）；不用生活类比、设问与 emoji | 完整自解释的句子，不依赖讲者在场补充；忌只有讲者能展开的电报式短语 |
| 交付形态 | HTML 放映为主 | **PPTX 常是硬要求**，阶段 4 就先用跨平台 `convert.py` 试导一次 | HTML 单文件直接分发，离线可拷走 |
| 模板起点 | `training-deck.html`（34 页全量） | `work-report-deck.html`（46 页，含五种复合高密度页型）；纯技术分享用 `tech-share-deck.html`（37 页） | 按内容取舍：偏教学用授课模板，偏综述用技术分享模板（见 `template-pages.md`） |

| # | 阶段 | 产出 | 闸门 |
|---|---|---|---|
| 1 | 主题讨论 | 需求共识（一段复述） | 用户确认 |
| 2 | 大纲规划 | 大纲表（章 / 分钟 / 页数），确认后落盘 `<deck名>.plan.md` | 用户确认 |
| 3 | 选择模板 | 页型映射表 | 随 4 一起给用户 |
| 4 | 初版制定 | 逐页规划表 + 初版 deck | — |
| 5 | 讨论修改 | 按页记录的修改清单 | 用户点头进终版 |
| 6 | 终版制作 | 终版 deck（+PPTX） | — |
| 7 | 讨论修改 | 交付确认 | 用户验收 |

## 1. 主题讨论

用户往往一句话提需求（「帮我做个 XX 的 PPT」）。开工前必须问清 **5 件事，一次问完，不挤牙膏**：

1. **听众是谁**：背景、人数、对主题的熟悉度（决定深度与术语量）
2. **场合与时长**：授课 / 汇报 / 学习材料自读？现场讲还是发出去看？多少分钟？（对照场景适配表定基调）
3. **讲完想达成什么**：听众离场时该记住 / 会做什么（决定主线）
4. **已有素材**：文档、数据、截图、旧 PPT、外链工具（决定哪些页有真料）
5. **品牌与交付**：用默认华为红还是要换品牌（`branding.md`）；交 HTML 还是 PPTX

产出：把以上五点整理成一段**需求共识**复述给用户确认，别自己脑补。

**用户催「时间紧，直接做」时**：把 5 问压缩成**带默认值的一轮快答**——每件事给出你的默认假设，用户只需纠偏（「都对」即可开工）。加速的是讨论的形式，不豁免确认的闸门。

## 2. 大纲规划

- 定章节结构与叙事主线，骨架按场景适配表选：授课走「抛问题 → 讲原理 → 看实践 → 巩固收尾」（模板的 问题页 / 研讨页 / 黑板题卡 就是为这条线备的）；汇报走**结论先行**；自读材料走手册式。
- 每章分配分钟数与页数预算，经验值见场景适配表（授课 1.5–2 分钟/页；汇报页数减半留问答；自读不受时长约束）。
- 产出大纲表：章号 / 章名 / 要回答的问题 / 分钟 / 页数。**用户确认前不碰模板。**
- **确认后立即落盘**：把大纲写成 deck 的伴生文件 `<deck名>.plan.md`，别只留在对话里（换会话 / 换人就丢）。**不要长**——章级几行 + 之后每页一行「这页要说啥」即可，格式：

  ```markdown
  # 我的演示 · 页面规划
  ## 大纲
  - 01 章名 — 本章要回答的问题（N 页）
  ## 逐页（阶段 4 补充，之后随改随更）
  | # | label | 这页要说啥（一句话） | 页型 | 配图 |
  ```

## 3. 选择模板

先按场景**确定且确认一套模板外壳**，再拿着大纲逐条映射到共享页型目录（查 `template-pages.md`）。三份 HTML 不合并：场景外壳决定封面、目录、感谢页和全局视觉基调；窗口化 Creation Draft 的 `creation templates` 会从 bundle 自动展开 34 / 37 / 46 个原生页型，并在 `availablePageTypes` 中加入 `compatibleWith` 明确允许借入当前外壳的页型。不得自造未登记的 `pageTypeId`，也不得到 `set-output` 时才临时换外壳；同名页型优先选当前外壳原生版本。

逐页规划必须包含三个固定页：第一张 `cover`、第二张 `toc`、最后一张 `thanks`。封面和感谢页从所选模板复制后只换必要文案；目录页保留模板外层版式与视觉语言，但内部目录项、layer 和逐章动画必须按实际大纲重建，绝不能直接继承模板的四章示例。三页都不是可选项，也不能用自制封面、简化目录或普通总结页代替。确认大纲时同步生成 `*.toc-contract.json`，目录的章数、章名和动画目标以该文件为权威，格式与验证命令见 `animation.md` 第 3.2 节。然后做整体节奏检查：

- 每章开头一张章扉页，重点章前抛一张问题页（10–15 分钟的短汇报不值得每章一张扉页，省掉或只留一张分隔）
- **连续 3 页同一视觉家族会被规划闸门拒绝**——换个卡片数量不算换版式；要在网格、分栏、流程、矩阵、证据、全图、观点页等家族之间切换
- 同页出现两个以上耦合维度时，先查 `density=dense` 且 `useWhen` 匹配的复合页型：阶段 + 责任 + 交付物用 `stage-deliverable-map`，系统 + 交付证据用 `system-map-output-rail`，功能分层 + 运维控制面用 `layered-platform-ops-rail`，双管线 + 原则门用 `method-pipeline-guardrails`，战略 + 能力缺口 + 项目组合用 `strategy-capability-portfolio`，代码 + 曲线 + 指标用 `code-curve-metrics`；不要拆成多页低信息卡片
- 密集页（密集多栏 / 表格混排）后面接轻页（全幅大图 / 金句）缓一口气
- 页型按场景适配表筛选：黑板题卡、研讨页是课堂专属，汇报与自读材料不用
- 仅授课：动手实验 / 研讨等互动页放在注意力低谷（大约每 15–20 分钟一次）
- 有真素材的内容优先选 截图对照 / 动手实验 等「用真料说话」的页型；「05 · 完整示例」章展示了各版式填入真内容的成品，选型拿不准时先翻它

产出：页型映射表（大纲条目 → 页型 → 来源模板 → 视觉家族 / 密度 → 理由一句），通常与阶段 4 的逐页规划表合并。借入其他模板的页型只改变这一页的结构来源，不改变整套 Deck 的场景外壳。

## 4. 初版制定

**先规划后动手。** 写逐页规划表，每页一行：

> 页序 | data-label | 页型 | 核心观点（一句话） | 排版逻辑 | 配图（类型 + 一句规格） | 拍数

- **核心观点 = 这页存在的理由，一句话**：授课是讲者站在这页前要说出的那句；汇报是要让听者接受的那个判断；自读材料是读者翻过这页前该记住的一句。写不成一句话，说明这页该拆；两页写出同一句，说明该合。
- **排版逻辑** = 信息怎么摆、为什么（如「左真实脚本右概念卡——用代码佐证概念」）。
- **配图 = 这页的图表规划，初版就定下来**：字不如表、表不如图——讲方法论 / 原理 / 流程的页，图或表是主表达；类型四选一（原图 / 自绘·流程 / 自绘·架构 / 表格）写进表格并落成页面上的类型化占位块（约定见 `artwork.md` 第 1 节）。
- `layoutRationale` 与 `artwork` 是内容页的必填规划字段；确实不需要配图时写「无」，不能留空让生成阶段自行猜测。
- 拍数先标 1（静态），动画节拍留到终版再精修。
- **文案三条纪律**：① 语言风格按场景适配表定调，初版就按终版口径写，别先写口水稿再改；② **绝不在页面上写「点击查看」「点击切换」类操作提示**——操作逻辑是讲者（或读者自己）的事，页面只放内容；真实功能控件的简短标签（「复制链接」等）除外；③ **落纸文字朴实且专业**——不写套话、广告词、空洞形容（「赋能」「极致」「重磅」「行业领先」一类）；也不用自造的比喻式短语代替技术描述（「整树换血」「华丽转身」「优雅收尾」一类，读者对不上具体动作）——讲流程、机制、步骤时直接写「动作 + 技术名称」（写「解析并替换 DOM」，不写「整树换血」）。授课场景中明确写成类比行的生活类比（如流程页的 🍲 类比行）是刻意的教学设计、不算违例，但类比只做辅助，技术句去掉类比后仍要独立成立。每句话都要有信息量。
- **标题即观点，且必须点名技术**：正文每一页的标题必须承载这一页的核心技术观点，或这一页在整个 deck 里的核心逻辑——写成有判断的句子，**并且把这页最重要的技术名词写进标题**（方法名 / 机制名 / 理论名），让读者知道效果记在哪个技术头上。常用句式：「基于 X（技术），实现 Y（效果）」「在 X 实验中，结合 Y（理论 / 方法），Z 指标提升 N」「在 X 场景，需要 Y 技术来确保 Z」「基于 X 理论，用 Y 技术穿刺，开发出 Z 工具 / 系统」。读者把全部标题连起来读就是完整论证链。三类反模式：栏目式名词标题（「系统架构」「实验结果」）；悬念式标题（只造气氛不给观点）；**有判断但无技术名词的标题**（「结构每复杂一步能解的题就难一档」——判断成立，但没说是哪个技术换来的，仍不合格）。标题写不出观点，说明逐页规划表里的「核心观点」一栏没想清楚，回去先改表。
- **模板组件优先于重新设计**：按页型来源复制整页 DOM，再替换内容；同一组、同一层级、同一语义角色的普通卡片沿用白底、1px 灰边、14px 圆角，并保持阴影、内边距以及标题 / 正文 / 标签的字体族、字号、字重、行距一致。只有页面文案明确表达选中、推荐、当前、风险或结论差异时才允许单卡高亮，不得为了构图制造默认高亮或红框。正文默认 ≥21px，内容纵向均衡铺开，不能用缩字或把内容堆在上半页来逃避排版。

然后按规划搭初版：复制模板产生合法 bundle → 给每页保留模板来源元数据，并按已确认 PagePlan 写入 `data-plan-page-id`、`data-plan-chapter-id` 与对应 `data-label` → 立即按 `SKILL.md` 的模式路由复用活动 Managed Workspace 或启动无窗口 Managed Workspace → 原生页按 `pageTypeId` 从当前外壳复制结构，共享页使用 `deck_factory.py import-page` 连同所需 manifest 资源受控导入（`editing-guide.md` 第 3 节）→ **配图一律先放类型化占位块**（`data-todo` 标记 + 类型 + 来源 + 内容规格，见 `artwork.md`），别在初版抠图画图 → 每改一批用 `cli.mjs verify` 建立检查点并跑必要的视觉验证。已有元素细节进入 ActionMutation，页面结构进入 SourceMutation；第一版制作不得继续在真实 Deck 上无历史直改。发布前必须通过页面规划、模板与目录三份契约检查：最终页数、顺序、页型、来源模板和页面身份与 PagePlan 完全一致，固定页仍在正确位置，封面 / 感谢页结构未变，目录章数、章名和逐章动画与大纲一致。交付含 PPTX 时（汇报常见），**初版就先用跨平台 `convert.py` 试导一次**——转换问题要在结构讨论前暴露，别拖到终版才发现。

产出：初版 deck + 逐页规划表。**逐页规划表写进 `<deck名>.plan.md` 的「逐页」节**（每页一行，一句话说清这页要说啥）——这个文件之后就是讲稿骨架和跨会话的修改依据，阶段 5–7 改页时随手同步它。

## 5. 讨论修改（初版）

- 把 deck 给用户在浏览器里从头过一遍，附上逐页规划表。
- **引导逐章反馈**，别只问「你看看怎么样」：每章问「这章的观点顺序对吗？哪页要增删？」
- 意见**按页记录**成修改清单，改完逐条回报（改了什么、在哪页、verify 是否过）。
- 结构性意见（挪章、删线索）在这一轮消化掉——终版阶段只做精修，不再动骨架。

闸门：用户明确点头「结构定了」，才进终版。

## 6. 终版制作

按顺序做精修（每步完成即验证）：

1. **配图落地**：按 `artwork.md` 清占位——素材 PDF 抽原图（PyMuPDF 裁切，多篇并行派 agent）、自绘流程 / 架构图（div 构件）、制表，逐个替换占位块，`data-todo` 计数归零；`embed_image` 嵌入（`editing-guide.md`），截图保留原生配色
2. **配动画节拍**（主要是授课场景）：按讲课节奏整拍设计（`animation.md`；「加动画」= 把整个知识节拍纳入同一 data-step，不是零散点缀）；汇报 / 自读材料按场景适配表少用或不用，此步可跳过
3. **品牌替换**：背景画 / 口号 / 人像 / 品牌色（`branding.md`，`apply_bg.py`）
4. **全量验证**：先运行 `cli.mjs verify`，再要求 `measure_overflow --all` 全零 + 重点页 `shot` 截图目检 + 动画页 `steps` 逐拍核对
5. 用户要求完成 / 保存 / 正式写入时执行 `cli.mjs solidify`，确认真实 Deck 已发布且统一撤销队列清空；仅预览时保留未固化 workspace 并明确告知
6. 需要 PPT 交付时用 `scripts/html2pptx/convert.py` 导出，抽查多标签页的展开效果

## 7. 讨论修改（终版）

- 最后一轮微调：文案措辞、数字核对、页序微调——只接受精修级改动，结构性返工要回到阶段 5 重新走闸门。
- 确认交付形态（HTML / PPTX / 两者），提醒：HTML 单文件离线可拷走，放映按 SKILL.md 开头的键位说明。
- 交付时附一句怎么继续自助改（改文案走 edit-bundle 最小代码块）。

## 常见错误

| 错误 | 后果 / 纠正 |
|---|---|
| 跳过 1、2 直接搭页 | 返工最大来源；用户催「直接做」时改用带默认值的一轮快答，不跳过 |
| 大纲 / 逐页规划只留在对话里 | 用户看不到全貌、换会话就丢；确认后落盘 `<deck名>.plan.md`，每页一行不要长 |
| 拿授课节奏做汇报 | 20 页塞进 10 分钟汇报必翻车：页数减半、结论先行、细节进附录备查 |
| 给自读材料 / 汇报堆动画 | 没有讲者推进就是障碍：自读基本不用；汇报少用且先试导 PPTX |
| 页面写「点击查看」类操作提示 | 操作逻辑是讲者的事，页面只放内容；发现即删（真实功能按钮标签除外） |
| 语言风格与场景错位 | 汇报里出现类比梗 / 设问 / 口语，或自读材料里全是电报式短语——按场景适配表校一遍全文 |
| 套话与广告词落纸 | 「赋能」「极致」「重磅」类词零信息量还显不专业；删掉或换成具体事实与数字 |
| 自造比喻词代替技术描述 | 「整树换血」「华丽转身」类修辞读者不知所指；改写成「动作 + 技术名称」（如「解析并替换 DOM」）。明确标注的教学类比行除外 |
| 栏目式 / 悬念式标题 | 「实验结果」「方案介绍」只标位置不带观点；标题要写成这页核心观点的判断句，全部标题连读 = 论证链 |
| 标题有观点但没点名技术 | 效果记不到具体技术头上；套「基于 X 实现 Y」句式把方法名 / 机制名 / 理论名补进标题 |
| 一页塞多个核心观点 | 观点写不成一句话就拆页 |
| 初版就抠图、调动画 | 结构没定，精修全是沉没成本；类型化占位块足够讨论 |
| 占位块不写类型与规格 | 终版落地时要重读全部素材；初版就写清【类型】+ 来源 + 内容一句（`artwork.md`） |
| 方法论页面全是文字卡 | 字不如表，表不如图——机制 / 流程 / 架构用自绘图做主表达，素材原图给证据 |
| 只问「你看看怎么样」 | 收不到可执行反馈；逐章提具体问题 |
| 改完不跑 verify 就给用户 | 溢出裁切是无声的，用户看到的比你以为的少一截 |
| 终版阶段接受结构性返工 | 回到阶段 5 重新走闸门，否则「终版」会无限循环 |
